## Approved decisions (2026-10-20)
See `build_conventions.md` §5: L200-C1 schema + `display_name`/`status`/`domain`/`subdomain`/`votes.source`; L200-C5 campaigns + `campaign_assets` + `completion_rule`; MCP tool names follow `review_*`/`campaign_*`/`metric_view_*`; MCP identity uses forwarded headers (verify post-deploy); in-app notifications only until webhook secrets exist; new tables `app_config`, `mcp_sessions`, `user_activity`, `notification_preferences`.

## Known risks carried into deploy
* ~~`pnpm-lock.yaml` is not regenerated by sessions (session 02 adds 3 deps).~~ **Resolved:** lockfile regenerated interactively (10,107 lines).
* ~~`@modelcontextprotocol/sdk` zod peer compatibility with zod 4.~~ **Resolved:** MCP SDK 1.32.1 accepts zod v4 natively. No conflict.
* Agent tools lack caller identity (read-only in V1); MCP calls may lack an OBO token (metric view tools degrade).
* Infra metric-view column drift vs. app schema (infra follow-up).
* `create_mcp_connection` isn't wired to a deploy hook; manual only.
* `@opentelemetry/api` isn't a direct dependency; span enrichment limited to `res.locals.otelAttributes`.
* RBAC group lookup fails open and logs at warn.
