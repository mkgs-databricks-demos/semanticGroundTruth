# Session 19: Deploy app and post-deploy job, fix until stable (Wave 7)

## Scope
Deploy the app to dev, diagnose deployment status and OTel logs, fix TypeScript and runtime errors within owned_paths, and repeat until the app is RUNNING with clean logs, the startup marker is present, and the post-deploy setup job has succeeded. This is a converge session: deploy → diagnose → fix → redeploy, up to 8 attempts.

## Context
* **Bundle:** `ground-truth-app`, target `dev`, app name `dev-semantic-ground-truth`.
* **Deploy commands:** `bundle deploy --target dev` then `bundle run app --target dev`. The `run_app_post_deploy` job_run resource auto-triggers `app_post_deploy_setup` on every deploy.
* **OTel logs:** `hls_fde_dev.dev_matthew_giglia_semantic_ground_truth.semantic_ground_truth_otel_logs`. Filter by `app.deployment_id` for the current deployment. TS errors have severity `UNKNOWN`; match them by body regex.
* **Startup marker:** `"listening on"` in logs indicates AppKit server ready.
* **Build pipeline:** `pnpm install` → `pnpm run build` (which runs `pnpm run build:server && pnpm run build:client`, i.e. `tsc -b` → `tsdown` → `vite build`).
* **TypeScript conventions:** `erasableSyntaxOnly` (no enums/namespaces in client/shared), type-only imports from express, no direct fetch in components/pages, `noUnusedLocals` / `noUnusedParameters` are ON (prefix unused with `_`).
* **Wilson score expected values:** `wilsonLowerBound(10, 10, 1.96) ≈ 0.7225`, `wilsonLowerBound(5, 10, 1.96) ≈ 0.2366`.
* **Lockfile:** Regenerated by the interactive session. `@modelcontextprotocol/sdk` resolved to `1.32.1` (accepts zod v4 natively). No zod conflict.
* **Post-deploy job:** `app_post_deploy_setup` grants M2M SPN `CAN_USE` on the app + UC grants (`USE CATALOG`, `USE SCHEMA`, `EXECUTE` on MCP service). It must succeed for MCP service connectivity.

## Known issues (from `tsc -b` run in interactive session — 50 errors total)

### Express `req.query` type mismatch (12 errors)
Express `req.query` values are `string | string[] | ParsedQs | ParsedQs[]`. Routes cast them directly to `string`. Fix: use `String(req.query.param)` or `parseQuery()` from `server/lib/http.ts`.
* `server/routes/admin.ts` (lines 46, 47)
* `server/routes/assets.ts` (lines 31, 32, 42, 43)
* `server/routes/campaigns.ts` (lines 43, 44, 54, 56)
* `server/routes/metricViews.ts` (lines 27, 37)

### MCP SDK `tool()` overload mismatch (10 errors)
`@modelcontextprotocol/sdk@1.32.1` may have a different `tool()` signature than the `^1.23.0` the code was written against. All in `server/mcp/tools/`:
* `campaign.ts` (lines 18, 39, 73)
* `metricView.ts` (lines 33, 58, 94)
* `review.ts` (lines 24, 64, 109, 161, 203, 222)

## Known risks (do NOT fix unless they block deploy)
* Agent tools have no caller identity (read-only in V1).
* MCP `metric_view_*` tools may degrade without an OBO user token through Unity Gateway.
* Infra metric-view columns may not match the app schema (infra follow-up).
* `create_mcp_connection` isn't wired to a deploy hook; it's manual only.
* `@opentelemetry/api` isn't a direct dependency; span enrichment limited to `res.locals.otelAttributes`.
* RBAC group lookup fails open and logs at warn.
